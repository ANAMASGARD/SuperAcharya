# Teacher contract research

Research snapshot: 9 November 2026. This is a research report and proposed acceptance contract, not an implementation or a deployment claim. Repository paths are relative to this document.

## Recommendation

Proceed with an authenticated, request-owned, cancellable teaching milestone behind Agent-Native's supported bring-your-own runtime. Keep PostgreSQL as the selected durable checkpoint backend. Defer a custom job worker, automatic restart execution, scheduling and distributed worker leases until a demonstrated requirement needs them. **Do not defer Stop, stale-generation rejection, duplicate-submission protection or two-tab overlap rejection.** These protect the first real conversation as soon as it can produce speech or side effects. This recommendation follows the installed runtime boundary and the project's existing interruption requirements; it is an engineering judgment, not a provider guarantee. [Installed runtime guide](../node_modules/@agent-native/core/docs/content/native-chat-ui.mdx), [project rules](../AGENTS.md)

Preserve the chosen pipeline: Gnani STT → LangGraph → OpenAI `gpt-6-luna` → Sarvam TTS. Keep Orchestrator, Input/Vision, Subject Tutor and Drawing Planner as four logical roles, invoked when needed. Clocked Fill/Decide are bounded tools inside the Orchestrator; they do not replace it or create a fifth independent assistant. A voice conversation is an intermediate milestone. The next batch should demonstrate an actual editable Excalidraw solution, drawn progressively from the same accepted steps that supply the narration. [Project workflow and delivery rules](../AGENTS.md)

## PostgreSQL checkpoints and execution ownership

Official LangGraph.js documentation names `PostgresSaver` from `@langchain/langgraph-checkpoint-postgres`, constructs it with `fromConnString`, and passes it to graph compilation. Its first-use `setup()` creates the required checkpoint storage. This is a separate package and storage setup, not automatic integration with this application's Drizzle migrations or its existing `postgres` client. Review and provision that setup deliberately; no installation or migration was performed here. [LangGraph PostgreSQL example](https://docs.langchain.com/oss/javascript/langgraph/add-memory)

Checkpoint storage preserves graph state. It does not authenticate a student, determine which tab owns audio, acknowledge an Excalidraw write, or schedule an invocation after a process restart. The documented resume examples require a caller to invoke the graph again with the matching thread identity. Plain nodes may run again from their beginning, so externally visible effects still need idempotency. [Checkpointers](https://docs.langchain.com/oss/javascript/langgraph/checkpointers), [resume semantics](https://docs.langchain.com/oss/javascript/langgraph/interrupts), [node replay](https://docs.langchain.com/oss/javascript/langgraph/graph-api)

**Proposed persistence policy:** PostgreSQL remains the selected backend for the running teacher. Use `MemorySaver` for isolated tests. An interactive, visibly non-durable development mode is a possible later choice, not an approved replacement for the selected PostgreSQL path. Never silently switch after PostgreSQL configuration, connection or migration failure. MemorySaver loses its checkpoints on process restart. Preserve the application's supported local board database separately; no claim is made that the official PostgreSQL saver can use PGlite directly. [LangGraph persistence](https://docs.langchain.com/oss/javascript/langgraph/persistence), [existing database initialization](../server/db/index.ts)

LangGraph documents `sync`, `async` and `exit` durability with different crash-loss tradeoffs. Choose and document the mode rather than treating a saved-checkpoint option as an unconditional recovery guarantee. Pending node writes help graph recovery but do not establish exactly-once provider calls or rendered board state. [Checkpoint durability](https://docs.langchain.com/oss/javascript/langgraph/checkpointers)

**Proposed first-milestone support boundary:** one declared Node execution process, request-owned runs, durable accepted data/checkpoints, and explicit user-driven continuation. A process-local controller registry can support that bounded deployment, but a browser-only busy flag cannot. Persisted run status must eventually identify abandoned runs as interrupted and permit a safe explicit next action; never leave an orphan occupying a permanent slot. Do not infer a dead run from a missing local controller in a multi-replica deployment. Automatic restart execution, cross-replica cancellation and seamless stream reattachment remain deferred until implemented and tested. These are application requirements inferred from the execution boundary, not capabilities supplied by `PostgresSaver`.

## Non-negotiable first-run invariants

The following are proposed implementation and acceptance requirements derived from the project's action, interruption and ownership rules; they are not claims about existing teacher code. [Project rules](../AGENTS.md)

| Concern | Required behavior |
| --- | --- |
| Finalized speech | A new recording gets a stable identity; finalization produces one immutable submission candidate. Only an explicit Send or the deliberately chosen finalization path may submit it. Partial/live updates, rerenders and provider phrase events cannot independently launch teaching. |
| Submission retry | Retrying the same logical input retains its submission ID and canonical payload. The server deduplicates by authenticated lesson and that identity. Repeating the same words in a new recording remains a new input; a transcript-text hash alone is insufficient. Reusing an ID with changed content is rejected. |
| Input quality | Empty, failed or truncated input does not silently become an accepted problem. Preserve the transcript for review and resolve mathematical ambiguity before presenting a final solution. A provider/model label on client data is not proof of server-verified provenance. |
| One active generation | Claim the lesson's run slot atomically before paid work. Concurrent submissions from two tabs must produce one accepted run and one explicit busy result, without duplicated audio or tool effects. The executor claim and the browser playback owner are separate responsibilities. |
| Conditional cancellation | Cancellation names the owned lesson and expected generation/run. An old Stop request is idempotent for its old run and cannot cancel or release a newer run. Completion/failure cleanup also releases only its own claim. |
| Immediate local Stop | Stop playback, empty buffered audio, invalidate the generation and cancel pending drawing before waiting for the server. Send authenticated cancellation, abort supported upstream work and release the logical slot. Late provider completion must not restore cancelled output. |
| Disconnect | Aborting the runtime stream, navigating away, or losing the producing request cancels its request-owned run. Wire the request signal and stream lifecycle through graph/model/tool/TTS adapters. An upstream service may continue already accepted work, so stale-output fencing remains mandatory. |
| State fencing | Every accepted write and emitted/playable item checks the current generation. Server commits must condition that check atomically with the write, not perform a separate stale-prone read. Clients also reject old-generation events. |
| Continuation | Preserve completed elements, accepted messages and acknowledged steps. A later follow-up/retry resumes or replans from accepted state; it does not replay old audio or duplicate teacher elements. A LangGraph human-input interrupt is distinct from aborting active media. |

Provider AbortSignals and graph interrupts are not interchangeable. LangGraph's human-input interrupt resumes by another invocation and re-enters the interrupted node. Its graceful-drain mechanism waits for the current superstep and does not itself cancel in-flight async work. Neither mechanism alone meets the classroom's immediate Stop requirement. [LangGraph interrupts](https://docs.langchain.com/oss/javascript/langgraph/interrupts), [fault tolerance](https://docs.langchain.com/oss/javascript/langgraph/fault-tolerance)

## Clocked contract: verified documentation, unverified live service

The web reader returned 403 for Clocked documentation, but read-only direct HTTPS retrieval succeeded. Context7 search did not identify a relevant Clocked documentation library. The facts below come from Clocked's own documentation, not the supplied review or an inferred SDK shape. No authenticated Clocked request was made.

| Item | Verified published contract |
| --- | --- |
| Fill endpoint | `POST https://clocked.rezolve.ai/clocked/fill`; text requests supply source `text`, named typed `fields`, and optional shared `instructions`. |
| Fill output | Raw HTTP returns `model` and `fields`, plus optional metadata. Each field has a value and type-dependent metadata; diagnostic fields are not universally required. |
| Verbatim extraction | An `extract` field defaults `infer` to true. Set `infer: false` when a preference must come from explicit source evidence. Generated/inferred values are not verbatim evidence. |
| Authentication | Required headers are Bearer authorization, JSON content type and a UUID `Idempotency-Key`. The credential stays on the backend. |
| SDK distinction | The JavaScript SDK wraps the HTTP result in `data`; raw HTTP does not. Image results have a separate contract and must not be parsed as text Fill fields. |

Sources: [Fill](https://clocked.rezolve.ai/docs/fill), [authentication](https://clocked.rezolve.ai/docs/authentication), [response envelopes](https://clocked.rezolve.ai/docs/responses).

Clocked documents source offsets as Unicode code-point positions, not JavaScript UTF-16 string offsets. Its confidence values describe model judgments, not guarantees. Preserve the original submitted text when checking evidence and calibrate any acceptance threshold on representative cases. [Source positions and confidence](https://clocked.rezolve.ai/docs/responses)

**Proposed use:** send a bounded onboarding/preferences excerpt to Fill inside the Orchestrator; validate returned language/grade/subject preferences, leave absent facts unknown, and persist only accepted values through shared actions. Do not send the whole lesson history unnecessarily. Decide can advise routing with an uncertainty path, but must never delay Stop or decide lesson ownership/authorization. Its text contract uses `state` and `questions`, with typed results under `answers`; it is not the Fill schema. [Decide](https://clocked.rezolve.ai/docs/decide), [project privacy/action requirements](../AGENTS.md)

Idempotency applies at several separate boundaries: student submission, Clocked logical request, accepted profile update, and each board operation. Retain Clocked's UUID and identical payload when the outcome is unknown. Do not generate a new UUID merely because a timeout occurred. A 409 can mean an in-progress request or conflicting payload; inspect it. `retryAsNew: true` ends automatic same-attempt recovery and requires a deliberate new attempt. Eligible retries remain bounded. These rules prevent a replayed provider result from becoming a duplicate application mutation only when the application also enforces its own idempotency. [Clocked errors and recovery](https://clocked.rezolve.ai/docs/errors)

The account gateway allows up to 110 seconds for a model request; published client timeouts are longer. A **three-second cutoff is therefore a proposed application budget**, not a documented Clocked response SLA. If retained, bound the whole optional attempt and its retries, then continue through an honest manual-preference/clarification path. Do not report successful extraction on fallback. Aborting the wait does not prove the provider stopped or was not charged; ignore late results for cancelled generations and retain the request identity for deliberate recovery. [Clocked timeout semantics](https://clocked.rezolve.ai/docs/errors)

Before claiming the adapter verified during implementation, run a minimal synthetic live request with configured credentials and inspect the actual status, raw envelope, null/missing fields, model and safe timing metadata. Also exercise replay/timeout handling in controlled tests. Credential validity, account permission/credits, observed response shape, latency distribution and language accuracy remain unverified here. This documentation task does not exercise the account.

## Model, speech and latency implications

OpenAI's current model page confirms `gpt-6-luna` image input, text output, streaming, structured outputs and reasoning levels `none`, `low`, `medium`, `high`, `xhigh`, `max`. It recommends Responses for tools; Chat Completions function calling is restricted to reasoning effort `none`. The installed OpenAI adapter recognizes the model identifier. Prefer the Responses path for the selected teacher tool workflow and verify the actual adapter request. These capabilities do not establish math correctness, project account access or measured lesson latency. [OpenAI model](https://developers.openai.com/api/docs/models/gpt-6-luna), [installed adapter declarations](../node_modules/@ai-sdk/openai/dist/index.d.ts)

Sarvam documents a TTS WebSocket with `Api-Subscription-Key`, configuration/text/flush messages, audio chunks and an optional synthesis-complete event. Its page currently lists multiple model generations and inconsistent default wording, so explicitly select a verified model/voice pair rather than inheriting a default or upgrading by assumption. Synthesis completion is not the browser's playback completion. English/Hindi/Hinglish output quality and audio-device behavior require project testing. [Sarvam streaming API](https://docs.sarvam.ai/api-reference/text-to-speech/stream)

**Proposed measurements:** record monotonic durations for microphone release → finalized transcript; accepted submission → first accepted teaching text/step; accepted step → first received audio; first audio → actual playback; and Stop → local silence plus server slot release. Report sample count and p50/p95 once enough real samples exist. Keep provider model-time headers separate from end-to-end timing. No fixed teacher response budget is established by the existing single-run Gnani observations. [Existing speech evidence boundary](speech.md), [Clocked timing semantics](https://clocked.rezolve.ai/docs/responses)

Use short accepted narration units to reduce time to useful output. Speech and future board commands must come from the same validated teaching step. Do not speak partial unvalidated structured JSON or claim word-to-stroke alignment without alignment data. This is the proposed product contract from [the project playback rules](../AGENTS.md), not an assertion that any provider supplies that synchronization automatically.

## Implications for the first approved implementation batch

Batch 1 should prove one authenticated, cancellable teacher conversation with Clocked-assisted preference extraction, existing Gnani input, LangGraph orchestration, `gpt-6-luna` output and Sarvam playback. Keep specialist invocation conditional; an unambiguous voice question does not justify fake Vision or Drawing Planner calls. PostgreSQL checkpoint persistence is part of the chosen durable path; an explicitly selected MemorySaver mode can support isolated tests. Define these acceptance checks before implementation:

1. An owned board maps to one authoritative native conversation; another user cannot read, run, cancel or modify it.
2. One finalized recording is accepted once. Live phrase updates, double Send, remounts and a lost-response retry cannot create duplicate teacher runs.
3. Two tabs racing to submit produce one active generation. The losing tab cannot play duplicate speech or acknowledge the winner's work.
4. Stop during Clocked, model generation and TTS playback is immediate locally. The server releases only the cancelled generation, and a new turn can start. Delayed old cancellation/finally callbacks cannot stop that new turn.
5. Request disconnect and navigation stop the request-owned workflow; deliberately injected late events cannot produce text, audio, profile writes or future board mutations.
6. Fill handles absent/uncertain preferences, malformed replies, 401/402/429, unknown network outcomes and the chosen cutoff truthfully. A live synthetic request is required before a real Clocked-integration claim.
7. A completed checkpoint is read back after process restart. An in-flight process failure is reported as interrupted; automatic execution recovery is not claimed. A later authenticated continuation restores accepted state without replaying previous audio. MemorySaver tests do not establish durable persistence; PostgreSQL failures never trigger a silent fallback.
8. Browser playback is verified with authenticated navigation, autoplay-denial text fallback, real Stop, next-turn success and console inspection. Stubbed provider tests are labelled as such; they do not establish real provider or microphone success.

The immediately following whiteboard batch should add one real math problem, Input/Vision where required, validated progressive operations, scene-state readback and acknowledgement, semantic undo, selection-aware explanation, interruption and correct continuation. Those capabilities must not be represented as complete after a voice-only batch. The same authorized actions must be demonstrated from both UI and agent paths. [Project acceptance criteria](../AGENTS.md)

For application changes, the repository requires typecheck, affected tests, doctor, production build and browser verification. `package.json` has `typecheck`, `test`, `agent-native:doctor` and `build`, but no lint script; report lint as unavailable rather than passed. This report adds documentation only: no application checks, build, browser run, paid provider calls, installations, migrations or Git staging/commit/push were performed. [Scripts](../package.json), [verification policy](../AGENTS.md)

## Research method and remaining limits

Read the review as review material, then checked the current repository and installed framework source. Ran local `docs-search` for `external-agents`, `agent-surfaces` and `native-chat-ui`, plus `source-search` for the action boundary. The optional framework template corpus was unavailable; existing installed runtime source was sufficient for the cited runtime facts, and nothing was installed. Read OpenAI/Sarvam primary documentation and Clocked's primary documentation through unauthenticated retrieval.

Exact LangGraph package compatibility, checkpoint setup permissions, connection-pool behavior with the chosen PostgreSQL deployment, graph cancellation propagation, authenticated native-thread integration and all live teacher behavior still require implementation-time verification. The user's explicit preference for undated project-memory entries remains in force; the review's suggestion to date them is not a new user instruction. Hackathon eligibility and submission deadlines were outside this technical research scope and were not independently verified.
